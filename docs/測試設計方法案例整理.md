## 一、等價類別劃分 (Equivalence Partitioning)

將輸入資料劃分為有效與無效的等價類別，從每個類別中選取代表值進行測試。

### 1.1 評分驗證測試

**測試檔案**：`tests/unit/api/create_review.test.js`

| 等價類別 | 輸入範圍 | 測試值 | 預期結果 |
|----------|----------|--------|----------|
| 有效類別 | 1-5 | 1, 4, 5 | 接受 ✅ |
| 無效類別 (過低) | < 1 | 0 | 拒絕 ❌ |
| 無效類別 (過高) | > 5 | 6 | 拒絕 ❌ |

```javascript
// 檔案: tests/unit/api/create_review.test.js

// ✅ 有效等價類別測試
it('should create review with valid data', async () => {
  const reviewData = {
    transaction_id: 123,
    score: 5,  // 有效評分 (1-5)
    comment: '非常好的賣家！'
  }
  const result = await createReview(reviewData)
  expect(result.score).toBe(5)
})

it('should create review without comment', async () => {
  const reviewData = {
    transaction_id: 123,
    score: 4  // 有效評分
  }
  const result = await createReview(reviewData)
  expect(result.score).toBe(4)
  expect(result.comment).toBeNull()
})

// ❌ 無效等價類別測試 - 評分過低
it('should throw error when score is below 1', async () => {
  const reviewData = { transaction_id: 123, score: 0 }
  await expect(createReview(reviewData))
    .rejects.toThrow('評分必須在 1-5 之間')
})

// ❌ 無效等價類別測試 - 評分過高
it('should throw error when score is above 5', async () => {
  const reviewData = { transaction_id: 123, score: 6 }
  await expect(createReview(reviewData))
    .rejects.toThrow('評分必須在 1-5 之間')
})
```

## 二、邊界值分析 (Boundary Value Analysis)

針對輸入範圍的邊界值進行測試，通常測試邊界值、邊界值±1。

### 2.1 點數等級邊界測試

**測試檔案**：`tests/unit/api/pointsAPI.test.js`

**等級邊界定義**：

| 等級 | 名稱 | 點數範圍 |
|------|------|----------|
| 1 | 新手交易者 | 0 - 499 |
| 2 | 初階交易者 | 500 - 999 |
| 3 | 中階交易者 | 1000 - 2499 |
| 4 | 進階交易者 | 2500 - 4999 |
| ... | ... | ... |
| 7 | 傳奇交易者 | 20000+ |

**邊界值測試案例**：

| 邊界 | 測試值 | 預期等級 |
|------|--------|----------|
| 等級 1 最小值 | 0 | LEVEL_TIERS[0] |
| 等級 1/2 邊界 | 750 | LEVEL_TIERS[1] |
| 等級 2/3 邊界 | 1500 | LEVEL_TIERS[2] |
| 等級 3/4 邊界 | 3000 | LEVEL_TIERS[3] |
| 等級 7 (最高) | 25000 | LEVEL_TIERS[6] |
| 負數 (異常值) | -100 | LEVEL_TIERS[0] |

```javascript
// 檔案: tests/unit/api/pointsAPI.test.js

describe('getLevelTier', () => {
  it('should return correct tier for given points', async () => {
    // 邊界值測試

    expect(getLevelTier(750)).toEqual(LEVEL_TIERS[1])    // 等級 2 中間值
    expect(getLevelTier(1500)).toEqual(LEVEL_TIERS[2])   // 等級 2/3 邊界
    expect(getLevelTier(3000)).toEqual(LEVEL_TIERS[3])   // 等級 3/4 邊界
    expect(getLevelTier(25000)).toEqual(LEVEL_TIERS[6])  // 最高等級
  })

  it('should return first tier for invalid points', async () => {
    // 負數邊界 (異常輸入)
    expect(getLevelTier(-100)).toEqual(LEVEL_TIERS[0])
  })
})
```

**測試檔案**：`tests/unit/api/save_locationAPI.test.js`

| 參數 | 有效範圍 | 測試的邊界值 |
|------|----------|-------------|
| 緯度 (latitude) | -90 ~ 90 | -91, -90, 90, 91 |
| 經度 (longitude) | -180 ~ 180 | -181, -180, 180, 181 |

```javascript
// 檔案: tests/unit/api/save_locationAPI.test.js

// 緯度邊界測試
it('應該在緯度無效時拋出錯誤', async () => {
  // 邊界值 -91 (低於下界 -90)
  await expect(
    saveUserLocation({ latitude: -91, longitude: 120.7344 })
  ).rejects.toThrow('Invalid latitude: must be between -90 and 90')

  // 邊界值 91 (高於上界 90)
  await expect(
    saveUserLocation({ latitude: 91, longitude: 120.7344 })
  ).rejects.toThrow('Invalid latitude: must be between -90 and 90')

  // 非數字輸入
  await expect(
    saveUserLocation({ latitude: 'abc', longitude: 120.7344 })
  ).rejects.toThrow('Invalid latitude: must be between -90 and 90')
})

// 經度邊界測試
it('應該在經度無效時拋出錯誤', async () => {
  // 邊界值 -181 (低於下界 -180)
  await expect(
    saveUserLocation({ latitude: 24.1817, longitude: -181 })
  ).rejects.toThrow('Invalid longitude: must be between -180 and 180')

  // 邊界值 181 (高於上界 180)
  await expect(
    saveUserLocation({ latitude: 24.1817, longitude: 181 })
  ).rejects.toThrow('Invalid longitude: must be between -180 and 180')

  // 非數字輸入
  await expect(
    saveUserLocation({ latitude: 24.1817, longitude: 'xyz' })
  ).rejects.toThrow('Invalid longitude: must be between -180 and 180')
})
```

## 三、狀態轉換測試 (State Transition Testing)

測試系統在不同狀態之間的轉換是否正確。

### 3.1 交易狀態轉換測試

**測試檔案**：`tests/unit/api/transaction_before_meetAPI.test.js`、`tests/unit/api/transactionAPI.test.js`

**狀態轉換圖**：

```
┌──────────┐   initiateTransaction   ┌────────────┐
│  (初始)  │ ───────────────────────► │ confirming │
└──────────┘                          └────────────┘
                                            │
                    ┌───────────────────────┼───────────────────────┐
                    │                       │                       │
            buyerConfirmTransaction    cancelTransaction      (自動超時)
                    │                       │                       │
                    ▼                       ▼                       ▼
             ┌───────────┐           ┌────────────┐          ┌────────────┐
             │  pending  │           │ cancelled  │          │  expired   │
             └───────────┘           └────────────┘          └────────────┘
                    │
        finalizeTransactionWithCode
                    │
                    ▼
             ┌───────────┐
             │ completed │
             └───────────┘
```

```javascript
// 檔案: tests/unit/api/transaction_before_meetAPI.test.js

describe('交易狀態轉換測試', () => {
  // 狀態轉換: (初始) → confirming
  it('should initiate a transaction successfully', async () => {
    const mockResponse = {
      transaction_id: 123,
      status: 'confirming',
      code: 'ABC123'
    }
    supabase.rpc.mockResolvedValueOnce({ data: mockResponse, error: null })

    const result = await initiateTransaction(456, 'buyer-uuid-123')
    
    expect(result.status).toBe('confirming')
    expect(result.code).toBeDefined()
  })

  // 狀態轉換: confirming → pending
  it('should confirm transaction successfully', async () => {
    const mockResponse = { success: true, new_status: 'pending' }
    supabase.rpc.mockResolvedValueOnce({ data: mockResponse, error: null })

    const result = await buyerConfirmTransaction(123, 'I will be there')
    
    expect(result.new_status).toBe('pending')
  })

  // 狀態轉換: confirming → cancelled
  it('should cancel transaction successfully', async () => {
    const mockResponse = { success: true, message: 'Transaction cancelled' }
    supabase.rpc.mockResolvedValueOnce({ data: mockResponse, error: null })

    const result = await cancelTransaction(123)
    
    expect(result.success).toBe(true)
  })
})

// 檔案: tests/unit/api/transaction_meetAPI.test.js

describe('transaction_meetAPI', () => {
  // 狀態轉換: pending → completed
  it('should finalize transaction with correct code', async () => {
    const mockUser = { id: 'user-123' }
    const mockResponse = {
      success: true,
      message: '交易完成',
      transaction_id: 456,
      new_status: 'completed'
    }

    supabase.auth.getUser.mockResolvedValueOnce({ data: { user: mockUser }, error: null })
    supabase.rpc.mockResolvedValueOnce({ data: mockResponse, error: null })

    const result = await finalizeTransactionWithCode(456, 'ABC123')

    expect(result.new_status).toBe('completed')
  })
})
```
