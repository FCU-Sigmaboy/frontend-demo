# 一、專題描述

## 1.1 專題題目

**FCU Sigmaboy 物品交換平台 - 前端應用程式軟體測試**

## 1.2 專題目標

本專案針對物品交換平台前端應用程式進行完整的軟體測試，**以 `src/api` 層為測試重點**，涵蓋網站核心功能的 API 模組測試。

## 1.3 功能說明

本平台提供以下 **8 個有意義的功能** (> 5 個 ✅)：

| # | 功能模組 | 功能說明 | 對應 API |
|---|---------|----------|----------|
| 1 | **用戶認證系統** | 使用者登入、登出、個人資料管理 | `get_userProfileAPI.js`, `update_myProfileDetailsAPI.js` |
| 2 | **物品刊登管理** | 物品建立、編輯、刪除、搜尋 | `create_myItemAPI.js`, `update_myItemAPI.js`, `get_searchItemsAPI.js` |
| 3 | **交易管理系統** | 發起交易、確認交易、取消交易、交易狀態追蹤 | `transactionsAPI.js`, `transaction_before_meetAPI.js`, `transaction_meetAPI.js` |
| 4 | **即時訊息系統** | 對話管理、即時訊息傳送、訊息通知 | `conversation.js` |
| 5 | **點數與獎勵系統** | 每日簽到、等級系統、徽章獎勵 | `pointsAPI.js`, `badgesAPI.js` |
| 6 | **評價系統** | 交易評價、評分、評論 | `create_review.js`, `get_my_reviews.js`, `get_others_reviews.js` |
| 7 | **地圖搜尋功能** | 地圖定位、附近物品搜尋 | `location.js`, `nominatimAPI.js`, `get_userLocationAPI.js` |
| 8 | **追蹤與收藏** | 追蹤用戶、收藏物品 | `followAPI.js`, `favorite.js` |

## 3.1 等價類別劃分 (Equivalence Partitioning)

### 範例：評分驗證測試

**等價類別定義：**
- 有效等價類：評分 1-5
- 無效等價類：評分 < 1 或 > 5

```javascript
// tests/unit/api/create_review.test.js

describe('評分等價類別測試', () => {
  // 有效等價類別
  describe('有效評分範圍 (1-5)', () => {
    it('評分 1 應該被接受', async () => {
      const result = await createReview({ rating: 1, ... })
      expect(result.success).toBe(true)
    })
    
    it('評分 3 應該被接受', async () => {
      const result = await createReview({ rating: 3, ... })
      expect(result.success).toBe(true)
    })
    
    it('評分 5 應該被接受', async () => {
      const result = await createReview({ rating: 5, ... })
      expect(result.success).toBe(true)
    })
  })
  
  // 無效等價類別
  describe('無效評分範圍', () => {
    it('評分 0 應該被拒絕', async () => {
      const result = await createReview({ rating: 0, ... })
      expect(result.error).toBeDefined()
    })
    
    it('評分 6 應該被拒絕', async () => {
      const result = await createReview({ rating: 6, ... })
      expect(result.error).toBeDefined()
    })
    
    it('評分 -1 應該被拒絕', async () => {
      const result = await createReview({ rating: -1, ... })
      expect(result.error).toBeDefined()
    })
  })
})
```

## 3.3 狀態轉換測試 (State Transition Testing)

### 交易狀態流程圖

```
                    ┌─────────────────────────────────────────────┐
                    │              交易狀態轉換圖                 │
                    └─────────────────────────────────────────────┘
                                          
    ┌──────────┐      發起交易      ┌─────────────┐     買家確認    ┌─────────────┐
    │  (無)    │ ─────────────────► │   pending   │ ──────────────► │ confirming  │
    └──────────┘                    └─────────────┘                 └─────────────┘
                                          │                               │
                                          │ 取消                          │ 確認碼驗證
                                          ▼                               ▼
                                    ┌─────────────┐                 ┌─────────────┐
                                    │  cancelled  │ ◄────────────── │  completed  │
                                    └─────────────┘      取消       └─────────────┘
```

```javascript
// tests/unit/api/transactionsAPI.test.js

describe('交易狀態轉換測試', () => {
  describe('有效狀態轉換', () => {
    it('pending → confirming (買家確認)', async () => {
      const transaction = { status: 'pending' }
      const result = await buyerConfirmTransaction(transaction.id)
      expect(result.data.status).toBe('confirming')
    })
    
    it('confirming → completed (確認碼驗證)', async () => {
      const transaction = { status: 'confirming' }
      const result = await finalizeTransactionWithCode(transaction.id, '123456')
      expect(result.data.status).toBe('completed')
    })
    
    it('pending → cancelled (取消交易)', async () => {
      const transaction = { status: 'pending' }
      const result = await cancelTransaction(transaction.id, 'reason')
      expect(result.data.status).toBe('cancelled')
    })
  })
  
  describe('無效狀態轉換', () => {
    it('completed → cancelled 應該失敗', async () => {
      const transaction = { status: 'completed' }
      const result = await cancelTransaction(transaction.id, 'reason')
      expect(result.error).toBeDefined()
    })
    
    it('cancelled → confirming 應該失敗', async () => {
      const transaction = { status: 'cancelled' }
      const result = await buyerConfirmTransaction(transaction.id)
      expect(result.error).toBeDefined()
    })
  })
})
```

### Bug #1: 點數格式化負數顯示錯誤

**問題描述：** 當點數為負數時，格式化函數顯示錯誤。

**發現方法：** 邊界值測試

**修復方式：**
```javascript
// Before (錯誤)
function formatPoints(points) {
  return points.toLocaleString()
}

// After (正確)
function formatPoints(points) {
  const absPoints = Math.abs(points)
  const formatted = absPoints.toLocaleString()
  return points < 0 ? `-${formatted}` : formatted
}
```

### Bug #3: 評分驗證範圍錯誤

**問題描述：** 評分允許 0 分，應該只允許 1-5 分。

**發現方法：** 等價類別測試

**修復方式：**
```javascript
// Before (錯誤)
if (rating < 0 || rating > 5) {
  return { error: '評分必須在 0-5 之間' }
}

// After (正確)
if (rating < 1 || rating > 5) {
  return { error: '評分必須在 1-5 之間' }
}
```

## 7.3 心得

### 測試開發心得

1. **測試驅動開發的重要性**
   - 先寫測試再寫程式碼能確保功能正確性
   - 測試案例是最好的文件

2. **覆蓋率不等於測試品質**
   - 高覆蓋率不代表測試完整
   - 邊界值和錯誤處理更重要

3. **Mock 策略的設計**
   - 統一的 Mock 設置能減少重複程式碼
   - 適當隔離外部依賴

4. **API 層測試的價值**
   - API 是業務邏輯的核心
   - 完整的 API 測試能確保系統穩定
