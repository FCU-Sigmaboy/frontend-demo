# 測試品質檢查清單

## 📋 程式碼審查檢查清單

### 測試結構 ✅

- [ ] **檔案命名**: 測試檔案使用 `.test.js` 或 `.spec.js` 後綴
- [ ] **目錄結構**: 測試檔案放在正確的目錄中（`tests/unit/api/`, `tests/unit/components/` 等）
- [ ] **描述區塊**: 使用有意義的 `describe` 區塊組織測試
- [ ] **測試命名**: 測試名稱清楚描述行為和期望結果
- [ ] **測試隔離**: 每個測試都是獨立的，不依賴其他測試

### 測試內容 ✅

- [ ] **AAA 模式**: 測試遵循 Arrange-Act-Assert 模式
- [ ] **單一職責**: 每個測試只驗證一個行為
- [ ] **邊界測試**: 包含邊界情況和錯誤處理測試
- [ ] **正面和負面**: 同時測試成功和失敗情況
- [ ] **有意義的斷言**: 使用具體的斷言而非模糊的檢查

### Vue 組件測試 ✅

- [ ] **Props 測試**: 測試所有重要的 props
- [ ] **事件測試**: 測試組件發出的事件
- [ ] **條件渲染**: 測試不同狀態下的渲染
- [ ] **用戶互動**: 測試點擊、輸入等用戶行為
- [ ] **插槽測試**: 如果使用插槽，要測試插槽內容

### API 測試 ✅

- [ ] **HTTP 模擬**: 正確模擬 HTTP 請求
- [ ] **錯誤處理**: 測試網路錯誤和 API 錯誤
- [ ] **參數驗證**: 測試 API 呼叫的參數
- [ ] **回應處理**: 測試不同的 API 回應格式
- [ ] **重試邏輯**: 如果有重試機制，要測試重試行為

### Store 測試 ✅

- [ ] **狀態變更**: 測試 actions 對 state 的影響
- [ ] **Getters**: 測試計算屬性的邏輯
- [ ] **非同步 Actions**: 正確測試非同步操作
- [ ] **錯誤狀態**: 測試錯誤狀態的處理
- [ ] **狀態隔離**: 每個測試使用獨立的 store 實例

### 模擬和替身 ✅

- [ ] **適當模擬**: 只模擬外部依賴，不模擬被測試的程式碼
- [ ] **模擬清理**: 在 `afterEach` 中清理模擬
- [ ] **模擬驗證**: 驗證模擬函數的呼叫次數和參數
- [ ] **真實行為**: 模擬應該反映真實的行為
- [ ] **時間控制**: 對時間敏感的測試使用假時間

### 效能和品質 ✅

- [ ] **執行速度**: 測試執行快速（< 100ms per test）
- [ ] **記憶體洩漏**: 沒有記憶體洩漏或未清理的資源
- [ ] **並行安全**: 測試可以並行執行
- [ ] **可重現性**: 測試結果一致且可重現
- [ ] **覆蓋率**: 達到設定的覆蓋率目標

## 🔍 程式碼品質檢查

### 測試可讀性 ✅

- [ ] **清晰命名**: 變數和函數名稱清楚表達意圖
- [ ] **適當註解**: 複雜邏輯有適當的註解說明
- [ ] **程式碼格式**: 遵循專案的程式碼格式規範
- [ ] **魔術數字**: 避免魔術數字，使用有意義的常數
- [ ] **重複程式碼**: 提取共用的測試邏輯到輔助函數

### 錯誤處理 ✅

- [ ] **異常測試**: 測試異常情況的處理
- [ ] **錯誤訊息**: 驗證錯誤訊息的內容
- [ ] **恢復機制**: 測試錯誤後的恢復邏輯
- [ ] **邊界條件**: 測試輸入的邊界條件
- [ ] **資源清理**: 確保錯誤情況下也能正確清理資源

### 維護性 ✅

- [ ] **測試更新**: 功能變更時同步更新測試
- [ ] **重構安全**: 測試不依賴實作細節
- [ ] **文件同步**: 測試與文件保持同步
- [ ] **版本相容**: 測試與依賴版本相容
- [ ] **技術債務**: 沒有被跳過或標記為 TODO 的測試

## 📝 提交前檢查清單

### 基本檢查 ✅

- [ ] 所有測試通過：`npm run test`
- [ ] 覆蓋率達標：`npm run test:coverage:check`
- [ ] 沒有跳過的測試（除非有充分理由）
- [ ] 沒有 console.log 或除錯程式碼
- [ ] 測試檔案格式正確
